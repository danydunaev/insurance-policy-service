# Сервис учёта страховых полисов

Консольное приложение на Python для автоматизации учёта страховых полисов клиентов страховой компании. Позволяет вести базу владельцев, их автомобилей и оформленных полисов ОСАГО/КАСКО, отслеживать сроки действия и рассчитывать стоимость продления.

## Назначение

Приложение решает задачи страхового агента:
- ведение базы клиентов (владельцев автомобилей);
- учёт автомобилей, привязанных к владельцам;
- оформление и хранение страховых полисов;
- контроль сроков действия (активен / истекает / истёк);
- поиск, фильтрация и сортировка полисов;
- расчёт стоимости продления с учётом коэффициентов;
- сохранение всех данных между запусками программы.

## Целевая аудитория

Менеджеры страховых компаний, страховые агенты, сотрудники отделов продаж и обслуживания клиентов.

## Предметная область

Страхование автотранспорта. Учёт взаимоотношений между клиентами, их транспортными средствами и оформленными полисами ОСАГО/КАСКО.

## Основные сущности

В проекте выделены **три основные сущности**, каждая из которых представлена **классом**:

- **User** — пользователь (владелец автомобиля);
- **Car** — автомобиль;
- **Policy** — страховой полис.

Дополнительно в полисе используются **атрибуты срока действия** — `start_date` и `end_date`. Это не отдельная сущность, а часть модели `Policy`.

## Основные классы

### Класс `User` — пользователь

Объект `User` представляет владельца автомобиля.

**Атрибуты:**
- `id` — уникальный идентификатор;
- `full_name` — ФИО владельца;
- `phone` — телефон;
- `email` — адрес электронной почты.

**Основные методы:**
- `__init__(user_id, full_name, phone, email)` — конструктор;
- `__str__()` — строковое представление;
- `from_data(data)` — `@classmethod` для создания объекта из словаря JSON;
- `to_data()` — преобразование объекта в словарь для JSON.

### Класс `Car` — автомобиль

Объект `Car` представляет транспортное средство, привязанное к владельцу.

**Атрибуты:**
- `id` — уникальный идентификатор;
- `owner` — **объект `User`** (ссылка на владельца);
- `license_plate` — госномер;
- `model` — марка/модель.

**Основные методы:**
- `__init__(car_id, owner, license_plate, model)` — конструктор;
- `__str__()` — строковое представление;
- `from_data(data, users)` — `@classmethod`, находит владельца в коллекции и создаёт объект;
- `to_data()` — преобразование в словарь для JSON.

### Класс `Policy` — страховой полис

Объект `Policy` представляет страховой полис и **связывает** объекты `User` и `Car`.

**Атрибуты:**
- `id` — уникальный идентификатор;
- `user` — **объект `User`** (владелец);
- `car` — **объект `Car`** (автомобиль);
- `company` — страховая компания;
- `policy_type` — тип (ОСАГО/КАСКО);
- `start_date` — дата начала;
- `end_date` — дата окончания;
- `price` — стоимость.

**Основные методы:**
- `__init__(...)` — конструктор;
- `__str__()` — строковое представление;
- `check_status()` — проверка срока действия: `истек`, `истекает (N дн.)`, `активен (N дн.)`;
- `calculate_renewal_price(is_accident_free, driver_age)` — расчёт стоимости продления с коэффициентами;
- `from_data(data, users, cars)` — `@classmethod`, создаёт полис с найденными объектами `User` и `Car`;
- `to_data()` — преобразование в словарь для JSON.

## Взаимодействие объектов

Объекты предметной области связаны между собой:

```
┌─────────────┐           ┌─────────────┐
│    User     │           │     Car     │
├─────────────┤           ├─────────────┤
│ id          │           │ id          │
│ full_name   │◄──────────│ owner       │
│ phone       │           │ license_plate│
│ email       │           │ model       │
└─────────────┘           └─────────────┘
       ▲                         ▲
       │                         │
       └────────┬────────────────┘
                │
           ┌─────────────┐
           │   Policy    │
           ├─────────────┤
           │ id          │
           │ user  ──────┼───► User
           │ car   ──────┼───► Car
           │ company     │
           │ policy_type │
           │ start_date  │
           │ end_date    │
           │ price       │
           └─────────────┘
```

- **User (1) → (N) Car** — один владелец может иметь несколько авто.
- **User (1) → (N) Policy** — один владелец может иметь несколько полисов.
- **Car (1) → (N) Policy** — один автомобиль может быть застрахован несколько раз.

Благодаря **композиции** объект `Policy` хранит **ссылки** на объекты `User` и `Car`, а не только их идентификаторы. Это позволяет обращаться к связанным данным напрямую:

```python
policy.user.full_name      # ФИО владельца
policy.car.license_plate   # госномер авто
```

## Возможности приложения

- **Пользователи:** добавление, поиск по ФИО, просмотр списка.
- **Автомобили:** добавление с привязкой к владельцу, поиск по госномеру, просмотр машин конкретного владельца.
- **Полисы:** добавление с привязкой к пользователю и автомобилю, проверка дубликатов.
- **Проверка статуса полиса:** активен / истекает (≤30 дней) / истёк.
- **Расчёт стоимости продления:** скидка 10% за безаварийность, надбавка 30% для водителей младше 25 лет.
- **Поиск полисов** по владельцу.
- **Фильтрация:** полисы, истекающие в ближайшие 30 дней.
- **Сортировка** полисов по цене (с использованием `lambda`).
- **Хранение данных** в JSON-файлах между запусками.

## Назначение модулей

### `main.py`

Точка входа приложения. Отвечает за:
- загрузку данных из JSON;
- отображение меню;
- получение данных от пользователя;
- организацию пользовательских сценариев.

### `models/users.py`

Содержит класс `User` и функции работы с коллекцией пользователей:
- `add_user()`, `get_user_by_id()`, `find_user_by_name()`.

### `models/cars.py`

Содержит класс `Car` и функции работы с коллекцией автомобилей:
- `add_car()`, `find_car_by_plate()`, `get_cars_by_owner()`.

### `models/policies.py`

Содержит класс `Policy` и функции работы с коллекцией полисов:
- `add_policy()`, `is_policy_duplicate()`, `find_policies_by_user()`, `get_expiring_soon()`, `sort_policies_by_price()`.

### `storage.py`

Отвечает за **преобразование JSON ↔ объекты**:
- при загрузке JSON-данные превращаются в объекты `User`, `Car`, `Policy`;
- при сохранении объекты превращаются в словари для JSON.

В JSON для `Policy` хранятся **идентификаторы** связанных объектов (`user_id`, `car_id`), а не сами объекты. При загрузке эти идентификаторы превращаются в ссылки на нужные объекты.

### `utils.py`

Содержит вспомогательные функции безопасного ввода:
- `input_str()`, `input_int()`, `input_float()`, `input_date()`.

### `tests/`

Содержит автоматизированные тесты проекта (pytest).

## Формат хранения данных

Данные сохраняются в JSON-файлах в каталоге `data/`:

- **`users.json`** — список пользователей:

```json
[
  {
    "id": 1,
    "full_name": "Иванов Иван Иванович",
    "phone": "+7-999-123-45-67",
    "email": "ivanov@example.com"
  }
]
```

- **`cars.json`** — список автомобилей:

```json
[
  {
    "id": 1,
    "owner_id": 1,
    "license_plate": "А123БВ77",
    "model": "Toyota Camry"
  }
]
```

- **`policies.json`** — список полисов:

```json
[
  {
    "id": 1,
    "user_id": 1,
    "car_id": 1,
    "company": "Ингосстрах",
    "policy_type": "ОСАГО",
    "start_date": "2025-01-01",
    "end_date": "2026-01-01",
    "price": 7500.0
  }
]
```

В файле `policies.json` хранятся **идентификаторы** (`user_id`, `car_id`), а не сами объекты. Это позволяет избежать дублирования данных. При загрузке программа автоматически восстанавливает связи между объектами.

## Использованные возможности Python

- **Классы и объекты** — `User`, `Car`, `Policy`.
- **Конструктор `__init__`** и **`__str__`** у каждого класса.
- **Композиция** — `Policy` содержит ссылки на `User` и `Car`.
- **`@classmethod`** — `from_data()` для загрузки объектов из JSON.
- **`@staticmethod`** — при необходимости для валидации (может быть добавлен).
- **Аннотации типов** — у всех функций и методов.
- **Docstring** — у всех функций и методов.
- **Коллекции** — `list[User]`, `list[Car]`, `list[Policy]`.
- **Циклы** — `for` для перебора, `while` для меню.
- **Исключения** — `try/except` в `utils.py` и `storage.py`.
- **Контекстные менеджеры** — `with open(...)`.
- **Lambda-функции** — ключ сортировки в `sort_policies_by_price`.
- **Работа с датами** — модуль `datetime`.
