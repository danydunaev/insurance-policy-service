# Сервис учёта страховых полисов

Приложение на Python для автоматизации учёта страховых полисов клиентов страховой компании. Изначально — консольное приложение (ПР1–ПР3), на ПР5 дополнено **веб-интерфейсом на Django**.

## Назначение

Приложение решает задачи страхового агента:
- ведение базы клиентов (владельцев автомобилей);
- учёт автомобилей, привязанных к владельцам;
- оформление и хранение страховых полисов;
- контроль сроков действия (активен / истекает / истёк);
- поиск, фильтрация и сортировка полисов;
- расчёт стоимости продления с учётом коэффициентов;
- сохранение данных между запусками программы;
- **просмотр данных через веб-интерфейс**.

## Используемые технологии

- **Python 3.10+** — язык программирования;
- **Django 5.2** — веб-фреймворк;
- **HTML** — разметка веб-страниц;
- **CSS и Bootstrap 5.3** — оформление страниц;
- **JSON** — формат хранения данных;
- **pytest** — автоматизированные тесты;
- **flake8** — проверка качества кода.

## Целевая аудитория

Менеджеры страховых компаний, страховые агенты, сотрудники отделов продаж и обслуживания клиентов.

## Предметная область

Страхование автотранспорта. Учёт взаимоотношений между клиентами, их транспортными средствами и оформленными полисами ОСАГО/КАСКО.

## Основные сущности

В проекте выделены **три основные сущности**, каждая из которых представлена **классом**:

- **User** — пользователь (владелец автомобиля);
- **Car** — автомобиль;
- **Policy** — страховой полис.

Дополнительно в полисе используются **атрибуты срока действия** — `start_date` и `end_date`. Это не отдельная сущность, а часть модели `Policy`.

## Основные классы

### Класс `User` — пользователь

Объект `User` представляет владельца автомобиля.

**Атрибуты:** `id`, `full_name`, `phone`, `email`.

**Методы:** `__init__`, `__str__`, `from_data` (`@classmethod`), `to_data`.

### Класс `Car` — автомобиль

Объект `Car` представляет транспортное средство, привязанное к владельцу.

**Атрибуты:** `id`, `owner` (объект `User`), `license_plate`, `model`.

**Методы:** `__init__`, `__str__`, `from_data` (`@classmethod`), `to_data`.

### Класс `Policy` — страховой полис

Объект `Policy` связывает объекты `User` и `Car`.

**Атрибуты:** `id`, `user` (объект `User`), `car` (объект `Car`), `company`, `policy_type`, `start_date`, `end_date`, `price`.

**Методы:** `__init__`, `__str__`, `check_status()`, `calculate_renewal_price()`, `from_data` (`@classmethod`), `to_data`.

## Взаимодействие объектов

- **User (1) → (N) Car** — один владелец может иметь несколько авто.
- **User (1) → (N) Policy** — один владелец может иметь несколько полисов.
- **Car (1) → (N) Policy** — один автомобиль может быть застрахован несколько раз.

Благодаря **композиции** объект `Policy` хранит **ссылки** на объекты `User` и `Car`. Это позволяет обращаться к связанным данным напрямую:

```python
policy.user.full_name      # ФИО владельца
policy.car.license_plate   # госномер авто
```

## Веб-интерфейс (Django, ПР5)

На ПР5 к консольному приложению добавлен **веб-интерфейс на Django**. Он использует те же классы и функции, что и консольная версия, — предметная логика ПР3 сохранена.

### Django-проект и приложения

- **`insurance/`** — пакет настроек Django-проекта;
- **`homepage`** — приложение главной страницы;
- **`web_users`** — приложение для отображения пользователей;
- **`web_policies`** — приложение для отображения полисов.

### Страницы веб-интерфейса

| URL | Страница | View-функция |
|-----|----------|--------------|
| `/` | Главная страница с навигацией | `homepage.views.index()` |
| `/users/` | Список пользователей | `web_users.views.users_list()` |
| `/policies/` | Список полисов | `web_policies.views.policies_list()` |
| `/policies/<int:policy_id>/` | Карточка полиса | `web_policies.views.policy_detail()` |
| любой несуществующий | Собственная страница 404 | `homepage.views.page_not_found()` |

### Что реализовано в вебе (ПР5)

- ✅ Главная страница с навигацией.
- ✅ Список пользователей из `data/users.json`.
- ✅ Список полисов с цветными бейджами статуса (активен / истекает / истёк).
- ✅ Карточка полиса с полной информацией.
- ✅ Собственная страница 404.
- ✅ Общий HTML-каркас (`page()`) с Bootstrap 5.3.

### Что отложено на следующие ПР

Операции, требующие форм и POST-запросов (добавление, редактирование, поиск, фильтрация), **пока остаются только в консольной версии**. Они будут перенесены в веб после изучения Django Forms и Django ORM.

## Возможности приложения

### Консольная версия (`python main.py`)

- **Пользователи:** добавление, поиск по ФИО, просмотр списка.
- **Автомобили:** добавление с привязкой к владельцу, поиск по госномеру.

- **Фильтрация:** полисы, истекающие в ближайшие 30 дней.
- **Сортировка** полисов по цене.
- **Хранение данных** в JSON-файлах.

### Веб-версия (`python manage.py runserver`)

- Просмотр списка пользователей.
- Просмотр списка полисов с цветными статусами.
- Просмотр карточки конкретного полиса.
- Навигация между разделами.
- Обработка ошибки 404.

## Формат хранения данных

Данные сохраняются в JSON-файлах в каталоге `data/`:

- **`users.json`** — список пользователей:

```json
[
  {
    "id": 1,
    "full_name": "Иванов Иван Иванович",
    "phone": "+7-999-123-45-67",
    "email": "ivanov@example.com"
  }
]
```

- **`cars.json`** — список автомобилей:

```json
[
  {
    "id": 1,
    "owner_id": 1,
    "license_plate": "А123БВ77",
    "model": "Toyota Camry"
  }
]
```

- **`policies.json`** — список полисов:

```json
[
  {
    "id": 1,
    "user_id": 1,
    "car_id": 1,
    "company": "Ингосстрах",
    "policy_type": "ОСАГО",
    "start_date": "2025-01-01",
    "end_date": "2026-01-01",
    "price": 7500.0
  }
]
```

В файле `policies.json` хранятся **идентификаторы** (`user_id`, `car_id`), а не сами объекты. При загрузке программа восстанавливает связи между объектами.
